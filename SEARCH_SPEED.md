# Скорость поиска через OpenAI: что сделано и что ещё можно

Цифры ниже — оценка по коду и типичным задержкам Responses API, не замер: в этой сессии не
было ключа OpenAI. Реальное время каждого шага показывает строка «Took … — …» под
результатами (`JobSearchStageTiming`), по ней и стоит проверять. Adzuna и Tavily по скорости
не трогал. Исключение — Adzuna теперь показывает результаты каждого тега сразу, как только
они пришли: это безопасно, запросы по-прежнему идут строго по очереди.

## Куда уходило время

До поиска у OpenAI-провайдера вызовов ИИ нет: подсказка query/tags запускается только для
Adzuna и по кнопке «Suggest from CV». Весь поиск — это два последовательных вызова.

| Шаг | Было | Оценка до | Стало | Оценка после |
|---|---|---|---|---|
| Чтение Personal Legend и ключей | по очереди | <0,1 с | параллельно | <0,1 с |
| Web search | support-модель, ответ прозой до 15 вакансий, без стриминга | 20–40 с | тот же вызов со стримингом, JSON Lines, до 10 вакансий, сниппет ≤ 25 слов | 15–35 с |
| Разбор результатов | второй вызов: до 40 000 символов текста + Personal Legend → JSON по схеме | 8–20 с | не нужен; только если модель ответила прозой | 0 с (запасной путь 3–8 с) |
| Первая вакансия на экране | в самом конце | 30–60 с | как только дописана первая строка | 12–25 с |
| **Всего** | | **30–60 с** | | **15–35 с** |
| «Suggest from CV» | вызов ИИ каждый раз | 3–8 с | из кэша, пока CV не менялось | ~0 с |

## Сделано

1. **Один вызов вместо двух.** Web search сразу пишет вакансии как JSON Lines: одна строка —
   один объект с полями `title/company/location/url/salary/postedAt/snippet`
   (`openai-provider.ts`, `listing-lines.ts`). Требования из старого прохода разбора
   (только живые вакансии, прямой URL, без выдуманной зарплаты, отсев неподходящих по
   уровню и профилю, negative prompt) перенесены в промпт поиска. Если модель всё же ответила
   прозой, текст разбирает старый `extractJobListings` с `reasoning.effort: "low"`, так что
   качество в худшем случае прежнее.
2. **Стриминг.** `streamWithWebSearch` в `openai/client.ts` читает SSE. Каждая готовая
   строка сразу проверяется (есть URL и название, вакансия не старше 30 дней, нет дубля) и
   уходит в панель как `JOB_SEARCH_PROGRESS`. В таймингах появился шаг «First result».
3. **Меньше вывода.** 10 вакансий вместо 15, сниппет — одно предложение до 25 слов. Задержку
   web search в основном определяет объём вывода. Следующие 10 даёт кнопка «More».
4. **Кэш подсказки query** для «Suggest from CV» (`job-search/suggestion-cache.ts`). Ключ —
   SHA-256 от города, страны, текста CV, Personal Legend и языков. Подсказка запроса и тегов
   идёт с `reasoning.effort: "low"`.
5. **`reasoning.effort` с запасным путём.** Если модель из настроек не принимает
   `reasoning`, клиент один раз повторяет запрос без него (`postResponses`).

Модель не менял: web search и раньше шёл через support-модель (`MODEL_LUNA`, быстрый
уровень). Уровень рассуждения у web search оставил по умолчанию: от него зависит, сколько
поисков сделает модель.

## Предложения (рискованнее, не сделано)

1. **`reasoning.effort: "low"` для web search.** Может срезать ещё 30–50 %, но модель,
   скорее всего, сделает меньше поисков и найдёт меньше живых вакансий. Проверять A/B на
   одном и том же Personal Legend по числу вакансий, которые открываются и не закрыты.
2. **`search_context_size: "low"`** у инструмента `web_search` (по умолчанию `medium`).
   Быстрее и дешевле, но модель видит меньше текста страницы, и чаще ошибается с датой
   публикации и зарплатой.
3. **Короче Personal Legend в промпте.** Сейчас легенда уходит целиком. Обрезка до ~4000
   символов немного ускорит старт ответа, но для длинной легенды ухудшит подбор.
4. **Заранее прогревать соединение и кэш** при открытии вкладки Search. Выигрыш —
   доли секунды, усложнение заметное.
5. **Строгая схема вместе с web search** (`tools` + `text.format: json_schema`). Это
   надёжнее JSON Lines, но такое сочетание не задокументировано как надёжное, а частичный
   JSON-документ нельзя показывать по ходу. Имеет смысл, только если запасной путь
   с разбором прозой будет срабатывать часто.
