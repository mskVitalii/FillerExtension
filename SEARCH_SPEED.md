# Скорость поиска вакансий: что сделано и что ещё можно

Цифры ниже — оценка по коду и типичным задержкам API, не замер: в этой сессии не было ключей
OpenAI/Adzuna/Tavily. Реальное время каждого шага показывает строка «Took … — …» под
результатами (`JobSearchStageTiming`), по ней и стоит проверять.

## Куда уходило время

За один поиск работает один провайдер, которого выбрал пользователь, так что распараллеливать
провайдеры между собой нечего. Время уходит внутри провайдера.

| Провайдер | Шаги до изменений | Оценка до | После | Оценка после |
|---|---|---|---|---|
| OpenAI | web search (support-модель, reasoning по умолчанию) → разбор (то же) | 30–60 с | разбор с `reasoning.effort: "low"` | 25–45 с |
| Tavily | Tavily `advanced` → разбор | 10–25 с | разбор с `low` | 5–12 с |
| Adzuna, поле пустое | подсказка query + tags (2 вызова ИИ параллельно) → до 12 запросов **строго по очереди** с паузой 350 мс | 15–25 с, всё в конце | подсказка из кэша; 3 запроса одновременно, старт каждые 350 мс; результаты по мере прихода | 5–7 с, первые через ~1 с; первый поиск по новому CV +3–8 с |
| «Suggest from CV» | 1–2 вызова ИИ каждый раз | 3–8 с | из кэша | ~0 с при неизменном CV |

## Сделано

1. **Adzuna: параллельные запросы по тегам** (`adzuna-provider.ts`). Раньше 12 тегов шли
   один за другим: 12 × (ответ + 350 мс). Теперь одновременно до 3 запросов, и каждый
   следующий стартует не раньше чем через 350 мс после предыдущего. Частота запросов не выше,
   чем у старого цикла в лучшем случае. На 429 один повтор через 1,2 с. Порядок результатов и
   привязка к тегу прежние.
2. **Результаты по мере поступления.** Фон рассылает `JOB_SEARCH_PROGRESS` с `searchId` после
   каждого тега, панель показывает их над скелетоном. Финальный `JOB_SEARCH_RESULTS` заменяет
   список целиком.
3. **Кэш подсказок query/tags** (`job-search/suggestion-cache.ts`). Ключ — SHA-256 от
   города, страны, текста CV, Personal Legend и языков, то есть ровно того, что читают оба
   промпта. Лежит в `chrome.storage.local`, до 4 записей. Изменили CV — промах кэша. В
   таймингах шаг называется «Suggest tags (cached)».
4. **`reasoning.effort: "low"`** для механических шагов: разбор результатов поиска,
   подсказка query и tags. Если модель из настроек не принимает `reasoning`, клиент повторяет
   запрос один раз без него (`postResponses` в `openai/client.ts`). Сам web search оставлен
   на уровне по умолчанию: от глубины рассуждения зависит, сколько поисков сделает модель, а
   значит и качество.
5. Мелочь: Personal Legend и ключи для OpenAI/Tavily читаются параллельно.

Модель: все эти шаги и раньше шли через support-модель (`MODEL_LUNA` по умолчанию), её не
трогал.

## Предложения (рискованнее, не сделано)

1. **Убрать второй вызов ИИ у OpenAI-провайдера.** Сейчас web search отдаёт текст, а
   отдельный вызов его разбирает. Это 25–40 % времени. Варианты: попросить web search сразу
   вернуть JSON по схеме (`tools` + `text.format` вместе; в коде отмечено, что это сочетание
   не задокументировано как надёжное) или парсить JSON из текста локально и звать разбор
   только при ошибке. Нужно сравнить качество на нескольких реальных поисках.
2. **`reasoning.effort: "low"` для самого web search.** Может дать −30–50 % времени, но
   модель, скорее всего, сделает меньше поисков и найдёт меньше живых вакансий. Стоит
   проверить A/B на одном и том же Personal Legend.
3. **Tavily `search_depth: "basic"` вместо `"advanced"`.** Примерно вдвое быстрее и дешевле,
   но сниппеты короче, и разбору сложнее отсеивать неподходящие вакансии.
4. **Стриминг разбора.** Разбор возвращает до 15 вакансий одним JSON. Если стримить и
   показывать каждую готовую вакансию, первая появится через пару секунд. Нужен потоковый
   разбор частичного JSON или формат «одна вакансия на строку».
5. **Сократить вход разбора.** Сейчас до 40 000 символов сырого текста плюс полный Personal
   Legend. Можно обрезать легенду до ~4000 символов и убрать из сырого текста markdown-ссылки
   и цитаты. Выигрыш небольшой: задержку в основном определяет вывод, а не вход.
6. **Adzuna: 4–5 параллельных запросов.** Лимит Adzuna в секунду не задокументирован.
   Ставить больше 3 стоит только после проверки на реальном ключе, что 429 не появляются.
7. **Предзагрузка подсказки.** При открытии вкладки Search заранее прогревать кэш
   query/tags, если CV изменился. Тогда первый поиск тоже не ждёт ИИ, но за подсказку
   придётся платить, даже если пользователь не нажмёт Search.
